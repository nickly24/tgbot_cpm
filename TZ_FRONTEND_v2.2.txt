Создать интерфейс для редактирования текстовых сообщений бота.

ФУНКЦИОНАЛ:
- Получить все сообщения при загрузке страницы
- Показать список сообщений с описанием каждого
- Для каждого сообщения - textarea для редактирования
- Кнопка "Сохранить" для каждого сообщения
- Показывать информацию о плейсхолдерах под полем ввода
- Toast-уведомление об успешном сохранении

API ENDPOINTS:

1. Получить все сообщения:
   GET /api/bot-messages
   
   Ответ:
   {
     "success": true,
     "data": {
       "welcome": "Привет! 👋\n\n...",
       "ask_status": "Приятно познакомиться, {name}! 😊...",
       "status_selected": "✅ Отлично! Вы выбрали...",
       "welcome_back": "С возвращением, {name}! 👋...",
       "message_received": "✅ Ваше сообщение получено...",
       "unsupported_message": "❌ Извините, я обрабатываю...",
       "need_status": "⚠️ Пожалуйста, сначала...",
       "admin_message_prefix": "📩 Сообщение от {admin_name}:\n\n"
     }
   }

2. Обновить конкретное сообщение:
   PUT /api/bot-messages/{message_key}
   
   Body:
   {
     "text": "Новый текст сообщения"
   }
   
   Ответ:
   {
     "success": true,
     "message": "Сообщение 'welcome' обновлено успешно"
   }

ПЛЕЙСХОЛДЕРЫ (показывать под полями):

welcome: нет плейсхолдеров
ask_status: {name} - имя пользователя
status_selected: {status_name} - название выбранного статуса
welcome_back: {name}, {status_name} - имя и статус пользователя
message_received: нет плейсхолдеров
unsupported_message: нет плейсхолдеров
need_status: нет плейсхолдеров
admin_message_prefix: {admin_name} - имя администратора

Создать интерфейс для управления статусами клиентов.

ФУНКЦИОНАЛ:
- Показать список всех статусов
- Отметить системные статусы (нельзя удалить)
- Возможность добавить новый статус
- Возможность редактировать название и эмодзи
- Возможность удалить статус (кроме системных)
- Drag & drop для изменения порядка (опционально)

API ENDPOINTS:

1. Получить все статусы:
   GET /api/config/statuses
   
   Ответ:
   {
     "success": true,
     "data": [
       {
         "value": "student",
         "label": "Студент",
         "emoji": "👨‍🎓",
         "is_system": true,
         "order": 0,
         "created_at": "2025-10-12T10:00:00"
       },
       {
         "value": "reserve",
         "label": "Резерв",
         "emoji": "📝",
         "is_system": true,
         "order": 1,
         "created_at": "2025-10-12T10:00:00"
       },
       {
         "value": "applicant",
         "label": "Абитуриент",
         "emoji": "🎓",
         "is_system": false,
         "order": 2,
         "created_at": "2025-10-12T10:00:00"
       }
     ]
   }

2. Добавить новый статус:
   POST /api/config/statuses
   
   Body:
   {
     "value": "vip",           // только латиница, цифры, подчеркивания
     "label": "VIP Клиент",   // любой текст
     "emoji": "⭐"             // опционально
   }
   
   Ответ:
   {
     "success": true,
     "message": "Статус добавлен успешно",
     "data": { ... }
   }

3. Обновить статус:
   PUT /api/config/statuses/{status_value}
   
   Body:
   {
     "label": "Новое название",  // обязательно
     "emoji": "🆕"               // опционально
   }
   
   Ответ:
   {
     "success": true,
     "message": "Статус обновлен успешно"
   }
   
   ⚠️ ДЛЯ СИСТЕМНЫХ СТАТУСОВ:
   Можно изменить только label и emoji
   Нельзя изменить value и удалить

4. Удалить статус:
   DELETE /api/config/statuses/{status_value}
   
   Ответ:
   {
     "success": true,
     "message": "Статус удален успешно"
   }
   
   Ошибка если системный:
   {
     "success": false,
     "error": "Нельзя удалить системный статус"
   }

🎨 РЕКОМЕНДАЦИИ ПО UI/UX

1. ЦВЕТА И СТИЛИ:
   - Системные статусы: серый замочек 🔒 или badge "Системный"
   - Кнопка удаления: красная с предупреждающей иконкой
   - Успешное действие: зеленый toast
   - Ошибка: красный toast или alert

2. ПОДТВЕРЖДЕНИЯ:
   - При удалении статуса: модальное окно "Вы уверены?"
   - Показать информацию: "Статус используется N пользователями"
   - Текст: "Это действие необратимо"

3. ВАЛИДАЦИЯ:
   - Value статуса: проверять на фронте перед отправкой
   - Regex: /^[a-zA-Z0-9_]+$/
   - Показывать ошибку сразу под полем

4. LOADING STATES:
   - При загрузке страницы: скелетон или спиннер
   - При сохранении: disable кнопки + текст "Сохранение..."
   - При удалении: disable кнопки + текст "Удаление..."

5. АДАПТИВНОСТЬ:
   - Страница должна работать на мобильных
   - Textarea должны растягиваться по высоте контента
   - На мобильных - кнопки на всю ширину

СЦЕНАРИЙ 1: Редактирование сообщения
1. Открыть страницу настроек
2. Изменить текст приветствия
3. Нажать "Сохранить"
4. Проверить в Telegram боте - должно измениться
5. ✅ Работает без перезапуска бота

СЦЕНАРИЙ 2: Добавление статуса
1. Открыть страницу настроек → статусы
2. Заполнить форму: value="vip", label="VIP", emoji="⭐"
3. Нажать "Добавить"
4. Статус должен появиться в списке
5. Открыть бота, /start - должна быть новая кнопка "⭐ VIP"
6. ✅ Работает без перезапуска

СЦЕНАРИЙ 3: Попытка удалить системный статус
1. Попытаться удалить "Студент"
2. Должна быть ошибка: "Нельзя удалить системный статус"
3. ✅ Защита работает

СЦЕНАРИЙ 4: Редактирование системного статуса
1. Нажать "Редактировать" у статуса "Студент"
2. Изменить label на "Студент МИРЭА"
3. Изменить emoji на "🎓"
4. Сохранить
5. В боте кнопка должна измениться на "🎓 Студент МИРЭА"
6. ✅ Редактирование работает

СЦЕНАРИЙ 5: Удаление пользовательского статуса
1. Добавить тестовый статус "test"
2. Удалить его
3. Модальное окно подтверждения
4. После подтверждения - статус исчезает
5. ✅ Удаление работает

   ⚠️ НЕ УДАЛЯТЬ плейсхолдеры {name}, {status_name}, {admin_name}

   ⚠️ student и reserve нельзя удалить
   Это критичные статусы для работы системы
   Можно изменить только label и emoji

3. VALUE СТАТУСА:
   ⚠️ После создания value нельзя изменить для не системных
   (это ограничение API можно добавить если нужно)
   Value используется в коде и БД

4. ОБНОВЛЕНИЕ В РЕАЛЬНОМ ВРЕМЕНИ:
   ✅ Все изменения применяются МГНОВЕННО
   ✅ Перезапуск бота НЕ требуется
   ✅ Бот читает данные из БД при каждом запросе

5. ОШИБКИ API:
   Обрабатывать коды ошибок:
   - 400: неверные данные
   - 403: нельзя удалить системный статус
   - 404: статус/сообщение не найдено
   - 500: ошибка сервера
