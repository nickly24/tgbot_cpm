## ✨ Основные изменения

### 1. 🔧 Настраиваемые сообщения бота

Теперь все текстовые сообщения, которые бот отправляет пользователям, можно редактировать через API без изменения кода!

**Что можно настраивать:**
- Приветственное сообщение при первом контакте
- Сообщение с просьбой выбрать статус
- Подтверждение выбора статуса
- Приветствие для возвращающихся пользователей
- Подтверждение получения сообщения
- Сообщение об ошибке (неподдерживаемый тип)
- Напоминание о выборе статуса
- Префикс для сообщений от администратора

**Новые API endpoints:**
- `GET /api/bot-messages` - получить все сообщения
- `PUT /api/bot-messages` - обновить все сообщения
- `GET /api/bot-messages/<key>` - получить конкретное сообщение
- `PUT /api/bot-messages/<key>` - обновить конкретное сообщение

**Плейсхолдеры:**
- `{name}` - имя пользователя
- `{status_name}` - название статуса
- `{admin_name}` - имя администратора

---

### 2. 👥 Динамические статусы клиентов

Статусы больше не зашиты в коде! Теперь их можно добавлять, редактировать и удалять через админку.

**Системные статусы (нельзя удалить):**
- `student` - Студент
- `reserve` - Резерв

**Возможности:**
- ✅ Добавление новых статусов
- ✅ Редактирование названий и эмодзи
- ✅ Изменение порядка отображения
- ✅ Удаление пользовательских статусов
- ❌ Защита системных статусов от удаления

**Новые API endpoints:**
- `GET /api/config/statuses` - получить все статусы (с полной информацией)
- `POST /api/config/statuses` - добавить новый статус
- `PUT /api/config/statuses/<value>` - обновить статус
- `DELETE /api/config/statuses/<value>` - удалить статус

**Формат статуса:**
```json
{
  "value": "vip",
  "label": "VIP Клиент",
  "emoji": "⭐",
  "is_system": false,
  "order": 5,
  "created_at": "2025-10-12T10:00:00.000000"
}
```

## 🗄️ Изменения в базе данных

### Новая коллекция: `config`

Два типа документов:

**1. Сообщения бота (`type: "bot_messages"`)**
```json
{
  "type": "bot_messages",
  "messages": {
    "welcome": "Привет! ...",
    "ask_status": "...",
    ...
  },
  "updated_at": "2025-10-12T10:00:00.000000"
}
```

**2. Статусы клиентов (`type: "client_statuses"`)**
```json
{
  "type": "client_statuses",
  "statuses": [
    {
      "value": "student",
      "label": "Студент",
      "emoji": "👨‍🎓",
      "is_system": true,
      "order": 0
    },
    ...
  ],
  "updated_at": "2025-10-12T10:00:00.000000"
}
```

### Автоинициализация

При первом запуске автоматически создаются дефолтные значения:
- 8 стандартных сообщений бота
- 5 статусов клиентов (2 системных + 3 пользовательских)

## 💡 Примеры использования

### Изменить приветственное сообщение

```bash
curl -X PUT http://0.0.0.0:80/api/bot-messages/welcome \
  -H "Content-Type: application/json" \
  -d '{"text": "Добро пожаловать! Как вас зовут?"}'
```

### Добавить новый статус

```bash
curl -X POST http://0.0.0.0:80/api/config/statuses \
  -H "Content-Type: application/json" \
  -d '{
    "value": "vip",
    "label": "VIP Клиент",
    "emoji": "⭐"
  }'
```

### Обновить статус

```bash
curl -X PUT http://0.0.0.0:80/api/config/statuses/applicant \
  -H "Content-Type: application/json" \
  -d '{"label": "Поступающий"}'
```

### Получить все настройки

```javascript
// Сообщения
const messages = await fetch('http://0.0.0.0:80/api/bot-messages')
  .then(r => r.json());

// Статусы
const statuses = await fetch('http://0.0.0.0:80/api/config/statuses')
  .then(r => r.json());
```

## ⚠️ Важные замечания

1. **Системные статусы** (`student`, `reserve`) защищены:
   - Нельзя удалить
   - Можно редактировать только `label` и `emoji`
   - Попытка удаления вернет ошибку 403

2. **Плейсхолдеры в сообщениях**:
   - Не удаляйте плейсхолдеры типа `{name}`
   - Бот использует их для подстановки данных
   - Неправильные плейсхолдеры могут сломать форматирование

3. **Валидация value статусов**:
   - Только латинские буквы, цифры и подчеркивания
   - Пример правильного: `vip_client`, `graduate2025`
   - Пример неправильного: `vip-client`, `выпускник`

4. **Изменения применяются мгновенно**:
   - Бот читает данные из БД при каждом запросе
   - Не требуется перезапуск
   - Изменения видны сразу всем пользователям
